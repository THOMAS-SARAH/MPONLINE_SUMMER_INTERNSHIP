## CMM (Capability Maturity Model) in SDLC

### What is CMM?

**Capability Maturity Model (CMM)** is a framework developed by the Software Engineering Institute to measure and improve the maturity of an organization's software development process.

It helps organizations improve the quality of software, reduce project risks, complete projects on time, and continuously enhance their Software Development Life Cycle (SDLC) processes.

In simple terms:

> **CMM tells us how mature and well-defined a company's software development process is.**

---

# Objectives of CMM

* Improve software quality
* Deliver projects on time and within budget
* Reduce defects and project failures
* Standardize software development processes
* Increase customer satisfaction
* Encourage continuous process improvement

---

# Why is CMM Important in SDLC?

During SDLC, many problems can occur:

* Poor planning
* Missed deadlines
* Budget overruns
* Low software quality
* Frequent requirement changes

CMM provides a structured process to manage these issues and improve software development efficiency.

---

# Five Levels of CMM

## Level 1 – Initial (Chaotic Process)

### Description

At this level, software development is unorganized and unpredictable.

Projects mainly depend on individual efforts rather than defined processes.

### Characteristics

* No standard process
* Poor documentation
* Success depends on skilled employees
* High risk of project failure
* Difficult to estimate cost and schedule

### Example

Two developers work on similar projects but use completely different methods because no company standards exist.

---

## Level 2 – Repeatable (Managed)

### Description

Basic project management practices are established.

Successful processes from previous projects are repeated in new projects.

### Characteristics

* Project planning is done
* Requirements are documented
* Cost estimation improves
* Schedule tracking exists
* Basic quality assurance is followed

### Example

A company uses the same testing and documentation process for every project.

---

## Level 3 – Defined

### Description

The organization has well-defined, documented, and standardized software development processes.

Every team follows the same SDLC methodology.

### Characteristics

* Standard SDLC process
* Coding standards
* Documentation standards
* Employee training
* Better communication among teams

### Example

Every project follows:

1. Requirement Analysis
2. Design
3. Coding
4. Testing
5. Deployment
6. Maintenance

---

## Level 4 – Managed (Quantitatively Managed)

### Description

Processes are measured using metrics.

The organization collects data to control quality and performance.

### Characteristics

* Software metrics are used
* Defect tracking
* Performance measurement
* Statistical quality control
* Risk management

### Example

The company measures:

* Defects per module
* Testing coverage
* Development time
* Customer complaints

Based on these measurements, improvements are made.

---

## Level 5 – Optimizing

### Description

The organization continuously improves its processes using feedback, innovation, and new technologies.

### Characteristics

* Continuous improvement
* Root cause analysis
* Automation
* Process optimization
* Adoption of new tools and technologies

### Example

The company introduces:

* Automated testing
* CI/CD pipelines
* AI-based code review
* DevOps practices

to further improve software quality and productivity.

---

# CMM Level Summary

| Level | Name                   | Description                                                           |
| ----- | ---------------------- | --------------------------------------------------------------------- |
| 1     | Initial                | No defined process; work is unpredictable.                            |
| 2     | Repeatable (Managed)   | Basic project management processes are established and repeatable.    |
| 3     | Defined                | Organization-wide standardized and documented processes are followed. |
| 4     | Quantitatively Managed | Processes are measured and controlled using metrics.                  |
| 5     | Optimizing             | Continuous process improvement through innovation and feedback.       |

---

# Advantages of CMM

* Improves software quality
* Reduces development cost
* Minimizes project risks
* Increases customer satisfaction
* Improves productivity
* Better project management
* Standardized development process
* Helps deliver projects on time
* Supports continuous improvement

---

# Disadvantages of CMM

* Expensive to implement
* Requires significant documentation
* Time-consuming to achieve higher maturity levels
* Needs employee training
* May be difficult for small organizations to adopt fully

---

# CMM and SDLC

CMM complements the SDLC by ensuring that every phase—requirements, design, implementation, testing, deployment, and maintenance—is carried out using mature, well-defined, and continuously improving processes. As an organization progresses through the five CMM levels, its SDLC becomes more predictable, efficient, and capable of delivering high-quality software.

---

## Exam Definition (2–3 Marks)

> **Capability Maturity Model (CMM)** is a process improvement framework that evaluates the maturity of an organization's software development processes. It consists of **five maturity levels**—Initial, Repeatable (Managed), Defined, Quantitatively Managed, and Optimizing—and helps organizations improve software quality, reduce risks, standardize development practices, and continuously enhance their SDLC processes.

---

## Key Points to Remember

* CMM stands for **Capability Maturity Model**.
* Developed by the Software Engineering Institute.
* Used to assess and improve software process maturity.
* Contains **five maturity levels**.
* Higher maturity levels lead to better quality, predictability, and continuous improvement in software development.
